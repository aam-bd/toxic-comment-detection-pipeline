Assignment 03

Transfer Learning, Fine-Tuning, Hyperparameter Tuning, and Interpretability

Given a comment written by a user, classify that text as toxic or not toxic. Train and evaluate this classifier on the Civil Comments dataset, and also test it on real-world text that you choose. The pipeline must demonstrate transfer learning, fine-tuning, hyperparameter tuning, and interpretability.

Dataset. Use the Civil Comments dataset: https://huggingface.co/datasets/google/civil_comments. Load it with load_dataset("google/civil_comments") from the Hugging Face datasets library. The comment is in the text column, and the toxicity column is a score between 0 and 1. Turn the score into a toxic or not toxic label with a threshold (for example, 0.5), and state your threshold in the README. You may reduce the dataset, for example by taking a random subset, if compute or time is limited.

You may use any hardware, a local machine, or a cloud environment (Google Colab). It is recommended that you use a Jupyter notebook.

Deadline: 7 days from the kick-off class (Sunday, 1 November 2026), that is, Sunday, 8 November 2026. No extension will be provided.

1. What the pipeline must do

  • Transfer learning. Load a pre-trained BERT-based language model and use it only as a frozen feature extractor. This run is your baseline, before hyperparameter tuning.
  • Fine-tuning. Unfreeze the model and fine-tune it end-to-end. Compare its final metrics with the frozen baseline.
  • Hyperparameter tuning. Tune the fine-tuned model. You choose which hyperparameters to search and which search method to use.
  • Interpretability. Explain a small, selected set of predictions. You may use SHAP, LIME, attention-weight visualization, or another suitable method.

2. What to submit in your GitHub project

  • The complete source code for the pipeline.
  • README.md is your technical report, and it must contain your name and your student ID. There is no page limit, but be as precise as possible. A README that omits your name or your student ID is incomplete. The README must include:
    • which BERT-based model you used, and why;
    • which explainability method you used, and why;
    • a justification of the results without tuning and with tuning;
    • a screenshot of the tuning results;
    • a test on real-world text, with the input, the predicted class, and a short check of that prediction;
    • the explainability analysis for a small set of predictions.
  • A .zip of the source code and the report only. Do not include the dataset, model checkpoints, cache files, virtual environments, or other large generated files.
  • A text file named github_link.txt containing the public repository link in the format required in Section 3.

3. GitHub repository

  • Configure the GitHub project repository as public, so that it is fully accessible without authentication.
  • Keep the repository publicly available for a minimum of one (1) year from the date of submission.
  • Any repository that is inaccessible, set to private, or no longer available will receive a score of zero.
  • The submitted repository link must use this format: https://github.com/YOUR_USER_NAME/YOUR_PROJECT_NAME

4. Grading

  • Correctness of the pipeline.
  • A logical comparison between the frozen baseline and the fine-tuned model.
  • The effort applied to hyperparameter tuning.
  • The clarity of the interpretability analysis.
